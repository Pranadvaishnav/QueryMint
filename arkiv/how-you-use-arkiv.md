# How QueryMint uses Arkiv

The buyer query reads actual publisher records from the `querymint.record.v1` schema using indexed dataset/category fields. The coordinator checks each entity owner against the publisher registered for the referenced dataset on Whitechain. Publisher-owned dataset manifests and records are visible to the publisher dashboard and the buyer preview; receipts connect the returned record hashes to settlement.

Expiry removes stale offers and records from the query surface. Only fields needed for discovery are indexed. These choices affect what buyers can find and what publishers control; Arkiv is not used only as an append-only log.

The publishing flow creates a publisher profile, a dataset manifest, and encrypted record entities with one Arkiv `executeBatch` call for a modest upload. The coordinator encrypts payloads using its server-held demo key before the batch; hashes distinguish the canonical plaintext content hash from the encrypted-payload hash. Entity references are persisted per dataset only after the batch confirms. The coordinator later queries indexed dataset/category fields, follows bounded keyset pages, checks the `$owner` against the Whitechain-registered publisher for that dataset, and validates payload/content hashes again during delivery.

The project owner reports that two publisher wallets wrote two datasets and four records on Rabdi, and the current production quote returned those four records. The successful live settlement and delivery are recorded in [live validation](../docs/live-validation.md). A current check of discovery is not a new Arkiv write or a guarantee that indexing will always be available. Arkiv entities are public; ciphertext protects licensed payloads only under the coordinator-key trust model documented in the [coordinator API guide](../docs/coordinator-api.md).
